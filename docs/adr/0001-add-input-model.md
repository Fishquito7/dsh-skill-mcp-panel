# 添加技能统一为「一个选择范围 + 一个分类器」

面板有三种添加入口（单文件、文件夹/zip、拖放），此前各自猜结构：文件夹选择器丢掉了被选中文件夹自己的名字，前端再用「路径恰好两段且以 SKILL.md 结尾」当门禁，于是合法技能包（如 `grill-with-docs/`）被误报缺少顶层 SKILL.md；反过来，技能包顶层与 `SKILL.md` 平铺的依赖 .md 又被当成独立技能逐个校验，误报格式不符合要求。

现在：任何入口都先把选择归一到**一个选择范围**，再交给**同一个分类器**，规则与 DSH 的发现机制对齐——选择范围内直接有 `SKILL.md` 就是**一个技能包**（整棵树是载荷，内部不再拆）；否则遍历（含 `SKILL.md` 的目录即技能包且不下钻，不含则继续下钻，深度上限与列表扫描一致），找到的技能一律**拍平到目标技能根第一层**（`<根>/<技能名>/` 或 `<根>/<文件名>.md`）。合法项逐个落盘，不合法 / 重名 / 冲突的逐条跳过并回报（部分成功）；一个都没成功才整体报错。

## Considered Options

- **按入口分别猜结构**：三个入口的语义不可能长期一致，这次的故障就是它的产物。
- **保留容器层级**（落盘为 `<根>/<容器>/<技能名>/`）：只有装了本插件的嵌套提供方才能发现它们，原生 DSH（只认一层）看不见；拍平后即使卸载插件技能依然有效。

## Consequences

- 选择文件夹的层级不会出现在技能根里：容器只是选择范围，分类请用面板的分组功能。
- 顶层 `SKILL.md` 优先于容器：技能包内部的子技能不在导入时拆出（运行时仍由嵌套提供方发现）。
- CLI 与面板共用同一份分类器（`src/skill-import.ts`），行为必须一致。
